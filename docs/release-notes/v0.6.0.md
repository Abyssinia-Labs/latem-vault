## OpenVault is now latem vault

This is the first published release, and the first under the new name. The command is `latem-vault`, its directory is `~/.latem-vault`, and the repository is [Abyssinia-Labs/latem-vault](https://github.com/Abyssinia-Labs/latem-vault). It changes no store version and no protocol: a device on 0.5 and one on 0.6 share a vault and sync with each other.

### Install

```sh
brew install abyssinia-labs/tap/latem-vault
```

For macOS and Linux, on arm64 and x86-64. The formula checks this release's signed checksums before it takes any of them. For this release only, it also installs an `openvault` command that says it is now `latem-vault` and runs it, so scripts that still call the old name keep working; the next release drops it.

### Coming from openvault

Nothing moves until you run a command. On a device that has `~/.openvault`:

```sh
latem-vault service install      # stops openvault's service, moves the vault, starts latem vault's
```

Any other command moves it too, while no service runs for it. The move is one rename of `~/.openvault` to `~/.latem-vault` on the same disk, so the key file and the Secure Enclave keys go with it, and it holds the service lock while it renames, so no service starts in between.

It waits, and keeps using `~/.openvault`, while openvault's service runs, while the Mac app's build looks only in the old directory, or while a latem older than 0.12.0 is installed, since that looks only in the old directory too. The command says on stderr which one is in the way. Update latem to 0.12.0 or later first.

`OPENVAULT_HOME`, `OPENVAULT_LOG` and `OPENVAULT_MDNS_SERVICE` are still read in 0.6, and go in a later release. Use `LATEM_VAULT_HOME`, `LATEM_VAULT_LOG` and `LATEM_VAULT_MDNS_SERVICE`.

### What keeps the name openvault

The names inside a vault never change with the brand: the key-derivation contexts, the signature labels, the key file magics, the protocol IDs (`openvault/sync/1` and the rest) and the mDNS service `_openvault._udp`. They are pinned in one module, `crates/crypto/src/frozen.rs`, whose tests fail if any of them changes. That is what lets 0.5 and 0.6 devices share a vault, and what keeps every existing vault readable.

### Also since 0.5.8

- **`latem-vault collections` says why it is empty** (0.5.9). It printed nothing on a device that had joined but hadn't synced. Now it says on stderr which case it is, and what to do: the vault has no collections yet, an admin hasn't given this device `read`, the service isn't running (`latem-vault service install`), or no device that reads them is on this network. On a Mac it mentions the Local Network permission. `join` ends with the same next step, and with no vault every command names `join` as well as `init`. Stdout stays empty, for scripts.
- **Signed releases.** Each release from now on is a tag on `main`, built for four platforms, with a checksums file signed by key `3AE5705FBEDAB5B2` ([latem-vault.pub](https://github.com/Abyssinia-Labs/latem-vault/blob/main/latem-vault.pub)).
